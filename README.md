# ScriptLint

一个以“反馈记忆”为核心的短剧人物一致性审计 Agent Demo。

用户可以导入自己的剧本文本，检查人物知情边界、动作能力、外观连续性、具体台词归属、情绪情境和道具连续性；用户提交改稿意见后，系统先生成待确认规则，只有人工确认的规则才会在同一项目的后续版本中自动复用。

## 当前能力

- 上传或粘贴 `.txt`、`.md`、`.fountain` 剧本文本；
- 保存项目、集数和 V1/V2 剧本版本；
- 自动发现台词头中的自定义角色名；
- 提取带原文与行号的人物事实；
- 发现伤口左右变化、已销毁道具再次出现等局部连续性矛盾；
- 将多条自然语言改稿意见拆为候选规则；
- 人工确认后，在后续版本按项目自动检索并应用；
- 同时展示改稿原话、剧本证据、应用理由和修复建议；
- 提供固定离线评测和匿名用户验证记录页。

## 尚未实现

- 当前不能上传或解析视频；
- 当前没有音频提取、ASR、说话人识别或字幕对齐；
- 当前不能根据画面判断动作、表情、服装和道具；
- 确定性文本解析器只覆盖声明支持的中文模式，不代表通用剧本理解能力。

视频音频审片和视觉审片的演进方案见 [MULTIMODAL_ROADMAP.md](MULTIMODAL_ROADMAP.md)。

## 本地运行

需要 Python 3.11 或更高版本。

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

浏览器访问 `http://localhost:8501`。

## 推荐体验路径

1. 使用自动生成的匿名项目代码，或设置自己的非敏感项目代码；
2. 导入一段已脱敏的剧本并保存为 V1；
3. 查看内部连续性发现和提取事实；
4. 提交 1–5 条明确改稿意见；
5. 逐条确认候选规则；
6. 导入修改后的 V2，保持项目代码不变；
7. 再次审计，观察确认记忆如何改变结果。

## 部署到 Streamlit Community Cloud

1. 将本仓库推送到 GitHub；
2. 在 Streamlit Community Cloud 创建应用；
3. 选择本仓库、目标分支和入口文件 `app.py`；
4. 部署后分享生成的 `streamlit.app` 地址。

当前使用单实例 SQLite，适合黑客松演示和少量测试，不适合生产环境。实例重启后数据可能无法长期保留；正式多人版本应更换为受控的云数据库、登录鉴权和按用户隔离的存储。

## 隐私

- 仓库不包含 API Key、真实用户数据、本地数据库或开发者本机路径；
- 每个新会话自动生成匿名项目代码；
- 重置只清理当前项目，不会清空其他项目；
- 公网 Demo 只应上传已脱敏、已获授权的短剧片段；
- 不要上传姓名、联系方式、合同、未公开商业剧本或其他敏感内容；
- 当前 Demo 没有账户系统，知道项目代码的人可能访问该项目的保存版本。

更多说明见 [SECURITY.md](SECURITY.md) 和 [USER_VALIDATION_PROTOCOL.md](USER_VALIDATION_PROTOCOL.md)。
